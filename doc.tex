\chapter{Ogólne wprowadzenie}
\section{Kaskadowe arkusze stylów}
Kaskadowe arkusze stylów (ang. \emph{Cascading Style Sheets}, w skrócie CSS) jest to deklaratywny język służący do kontrolowania prezentacji dokumentów HTML, XML, SVG itp.

Historia CSS sięga lat 90. XX wieku, kiedy to został stworzony jako odpowiedź na potrzebę oddzielenia struktury dokumentu od jego stylizacji. Wcześniej wszystkie style były zdefiniowane bezpośrednio w kodzie HTML, co sprawiało, że utrzymanie i zarządzanie stronami internetowymi było trudne i niewydajne.

Za pomocą CSS można kontrolować różne aspekty prezentacji, takie jak kolory, czcionki, marginesy, odstępy między elementami, rozmiar i położenie elementów na stronie, animacje itp.


Dla przykładu, poniższy kod zmienia kolor akapitu na czerwony:
\begin{lstlisting}
p {
  color: red;
}
\end{lstlisting}

Język CSS jest stale rozwijany, co oznacza, że pojawiają się nowe funkcje i możliwości, które pozwalają projektantom jeszcze lepiej kontrolować wygląd swoich stron internetowych. Istnieją również różne wersje CSS, z których najnowsza, CSS3, wprowadza wiele nowych funkcji, takich jak efekty przejścia, animacje, gradienty czy elastyczne rozkładanie elementów.

\section{Metodologia \emph{Blok Element Modyfikator}}
\emph{Blok Element Modyfikator} (w skrócie BEM) jest to metodologia ułatwiająca tworzenie komponentów wielokrotnego użytku.

Historia BEM sięga 2009 roku, kiedy została wprowadzona przez zespół deweloperów w Mail.Ru, jednej z największych rosyjskich firm internetowych. Jej celem było rozwiązanie problemów związanych z rosnącą złożonością stron internetowych i aplikacji oraz utrzymaniem spójności i czytelności kodu CSS.


Zgodnie z metodologia BEM nazwa każdej z klas CSS musi składać się z trzech elementów:
\begin{itemize}
  \item Blok (ang. \emph{Block}) - niezależny komponent, który stanowi podstawową część struktury interfejsu. Blok może zawierać inne bloki lub elementy. Każdy blok ma unikalną nazwę, która jest używana w klasach CSS do identyfikacji jego stylów, np. \lstinline{.header}, \lstinline{.container}, \lstinline{.menu}, \lstinline{.checkbox}, \lstinline{.input}.

  \item Element (ang. \emph{Element}) - część składowa bloku, która ma znaczenie tylko w kontekście tego bloku. Elementy są zależne od bloku, w którym się znajdują, i nie mogą istnieć samodzielnie poza nim. Nazwy elementów są prefiksowane nazwą bloku, do którego należą, i oddzielone dwoma podkreślnikami, np. \lstinline{.menu__item}, \lstinline{.list__item}, \lstinline{.checkbox__caption}, \lstinline{.header__title}.

  \item Modyfikator (ang. \emph{Modifier}) - odpowiada za zmianę wyglądu lub zachowania bloku lub elementu. Dzięki modyfikatorom możliwe jest dostosowywanie wyglądu i funkcjonalności istniejących bloków i elementów bez konieczności tworzenia nowych. Nazwy modyfikatorów są prefiksowane nazwą bloku lub elementu, do którego się odnoszą, i oddzielone dwoma minusami, np. \lstinline{.btn--disabled}, \lstinline{.link--highlighted}, \lstinline{.checkbox--checked}, \lstinline{.nav--fixed}, \lstinline{.nav__link--size-big}, \lstinline{.nav__link--color-yellow}.
\end{itemize}





\section{Semantyczny CSS}
Semantyczny CSS jest to metodologia, której jednym z największych priorytetów jest \textit{separacja obowiązków} \cite{Wathan2017}.

Idea ta zakłada, że HTML powinien zawierać tylko informacje dotyczące treści, a wszystkie decyzje dotyczące stylizacji powinny być podejmowane w kodzie CSS.

Dla przykładu:
\begin{lstlisting}[language=HTML]
  <p class="text-center">
    Hello world!
  </p>
\end{lstlisting}

Kod zawiera jedną klasę \lstinline{.text-center}. Centrowanie tekstu to decyzja stylistyczna, więc ten kod łamie zasadę \textit{separacji obowiązków}, ponieważ pozwoliliśmy, aby informacje dotyczące stylizacji przeniknęły do naszego HTML-a.

Zamiast tego, zalecane podejście polega na nadawaniu elementom nazw klas na podstawie ich zawartości i wykorzystaniu tych klas jako punktów zaczepienia w kodzie CSS do stylizacji kodu:
\begin{lstlisting}[language=HTML]
  <style>
  .greeting {
      text-align: center;
  }
  </style>
  
  <p class="greeting">
      Hello world!
  </p>
\end{lstlisting}

\section{Wszechstronny CSS}
Wszechstronny CSS (ang. \emph{utility-first CSS}) to podejście odwrotne do Semantycznego CSS. Skupia się na tworzeniu małych, pojedynczych klas CSS, z których każda odpowiada za jedną, konkretną właściwość stylu. Zamiast tworzyć specjalne klasy dla konkretnych elementów interfejsu użytkownika, jak nagłówki, przyciski itp. używa się klas, które definiują pojedyncze właściwości CSS, takie jak kolor, margines czy wypełnienie.

\section{Statyczny CSS}
Statyczny CSS to metodologia, w której kod CSS nie zmienia się w trakcie działania aplikacji. Kod CSS jest pisany wprost lub generowany na etapie kompilacji po przeanalizowaniu kodu. Tworząc kod w ten sposób, możemy skorzystać z wachlarza narzędzi, analizujących i modyfikujących kod CSS w celu znalezienia błędów, zminimalizowania lub polyfillowania kodu\footnote{polyfillowania kodu -- zastąpienia kodu niewspieranego przez niektóre przeglądarki równoważnym działającym kodem \cite{Lawson2011-fr}}.
\section{Programowy CSS}
Programowy CSS to z kolei metodologia, w której style CSS są tworzone w trakcie działania aplikacji. Przewagą tego rozwiązania nad statycznym CSS przez wiele lat była możliwość generowania stylów dynamicznych. Zastosowanie tej metodologii nie wymaga szerokiej znajomości języka CSS -- style zwykle definiowane są przy użyciu bibliotek, które zapewniają wysoko poziomowy interfejs. Wykorzystując tego typu biblioteki w językach z silnym typowaniem, możemy automatycznie korzystać z auto uzupełniania kodu i raportowania błędów w edytorze bez dodatkowych narzędzi, wymaganych do zrozumienia składni języka CSS.


\chapter{Struktura HTML}
Struktura HTML może być reprezentowana jako drzewo, co jest przydatne do wizualizacji hierarchii elementów oraz do manipulacji dokumentem w języku JavaScript. To drzewo nazywane jest drzewem DOM (ang. \emph{Document Object Model}). Na listingu \ref{dom} widzimy przykład kodu HTML. Kod ten można przedstawić jako drzewo.

\begin{lstlisting}[language=HTML,caption={Przykładowy kod HTML},label={dom}]
  <!DOCTYPE html>
  <html>
  <head>
    <title>Struktura HTML</title>
  </head>
  <body>
      <h1>Witamy!</h1>
      <p>To jest akapit.</p>
      <div>
          <span>Kolejny akapit w elemencie div.</span>
      </div>
  </body>
  </html>
\end{lstlisting}

\section{Korzeń drzewa}
Korzeń drzewa, to węzeł, który jest na szczycie hierarchii drzewa i od którego wszystkie inne węzły (elementy) są bezpośrednio lub pośrednio zależne. Korzeń jest jedynym węzłem w drzewie, który nie ma rodzica. Wszystkie inne węzły w drzewie są jego potomkami. W listingu \ref{dom} widzimy przykład drzewa, w którym element \lstinline|<html>| jest korzeniem drzewa.

\section{Dziecko i Rodzic}
Dziecko (ang. \emph{child}) jest węzłem, który jest bezpośrednio podłączony do innego węzła, zwanego jego rodzicem (ang. \emph{parent}). Węzeł rodzic może mieć wiele dzieci, ale każde dziecko ma tylko jednego rodzica. W listingu \ref{dom} widzimy przykład drzewa, w którym element \lstinline|<title>| jest dzieckiem elementu \lstinline|<head>|.


\section{Potomek i Przodek}
Potomek (ang. \emph{descendant}) jest węzłem, który znajduje się w hierarchii drzewa poniżej innego węzła, zwanego przodkiem (ang. \emph{ancestor}). W listingu \ref{dom} widzimy przykład drzewa, w którym element \lstinline|<span>| jest potomkiem elementu \lstinline|<body>|.



\section{Liść}
Liść (ang. \emph{leaf}) jest węzłem, który nie ma żadnych dzieci. Są to elementy najniżej położone w hierarchii drzewa. W listingu \ref{dom} widzimy przykład drzewa, w którym tekst "Witamy!" jest liściem.

\section{Rodzeństwo}
Rodzeństwo (ang. \emph{sibling}) odnosi się do węzłów, które mają tego samego rodzica. Rodzeństwo to elementy znajdujące się na tym samym poziomie hierarchii drzewa, bezpośrednio obok siebie. W listingu \ref{dom} widzimy przykład drzewa, w którym elementy \lstinline|<p>|, \lstinline|<div>|, \lstinline|<h1>| są rodzeństwem.

\section{Sąsiadujące rodzeństwo}
Sąsiadujące rodzeństwo (ang. \emph{adjacent siblings}) odnosi się do dwóch węzłów w strukturze drzewa, które mają tego samego rodzica i sąsiadują ze sobą bezpośrednio na tym samym poziomie hierarchii, nie mając żadnego innego węzła pomiędzy nimi na tym samym poziomie hierarchii. W listingu \ref{dom} widzimy przykład drzewa, w którym element \lstinline|<h1>| ma tylko jedno sąsiadujące rodzeństwo element \lstinline|<p>|.

\section{Młodsze rodzeństwo}
Młodsze rodzeństwo (ang. \emph{younger sibling}) jest węzłem, który znajduje się na tym samym poziomie hierarchii co inny węzeł, ale jest umieszczony po nim. W praktyce oznacza to, że oba węzły mają tego samego rodzica, ale młodsze rodzeństwo występuje później w kolejności. W listingu \ref{dom} widzimy przykład drzewa, w którym element \lstinline|<p>| i \lstinline|<div>| są młodszym rodzeństwem elementu \lstinline|<h1>|.





\chapter{Najczęściej wykorzystywane funkcjonalności języka CSS}
Składnia arkusza stylów CSS przedstawiona jest na listingu \ref{stylesheet_syntax}. Jednym z głównych elementów tej składni są zestawy reguł\footnote{zestaw reguł - Termin zestaw reguł jest często nazywany po prostu regułą}, których składnia przedstawiona jest na listingu \ref{ruleset_syntax}. Na rysunku \ref{rysunek} widzimy przykład takiej reguły, składającej się z selektora elementu \lstinline|p| oznaczonego niebieskim kolorem, oraz zbioru deklaracji, znajdującego się pomiędzy nawiasami. W zbiorze deklaracji na tym rysunku widzimy tylko jedną deklarację \lstinline|color: red;| składającą się z atrybutu oznaczonego kolorem czerwonym, dwukropka, wartości atrybutu i średnika. Każda reguła musi składać się z co najmniej jednej deklaracji.


\begin{lstlisting}[caption={Składnia arkusza stylów CSS \cite{GrammarofCSS}},label={stylesheet_syntax}]
stylesheet
  : [ CHARSET_SYM STRING ';' ]?
    [S|CDO|CDC]* [ import [ CDO S* | CDC S* ]* ]*
    [ [ ruleset | media | page ] [ CDO S* | CDC S* ]* ]*
  ;
\end{lstlisting}

\begin{lstlisting}[caption={Składnia reguły CSS \cite{GrammarofCSS}},label={ruleset_syntax}]
  ruleset
    : selector [ ',' S* selector ]*
      '{' S* declaration? [ ';' S* declaration? ]* '}' S*
    ;
  
  declaration
    : property ':' S* expr prio?
    ;
\end{lstlisting}

\section{Selektory}

\end{lstlisting}

\section{Nadpisywanie stylów}
Jeśli istnieją dwie lub więcej reguł CSS wskazujących na ten sam element, selektor o najwyższej specyficzności "wygra", i jego deklaracja stylu zostanie zastosowana do tego elementu HTML.
Dla przykładu listing \ref{nadpisywanie_stylow}.


\begin{lstlisting}[language=HTML, label={nadpisywanie_stylow}, caption={Tekst akapitu będzie zielony, ponieważ reguła \lstinline{.test} ma najwyższą specyficzność}]
  <html>
  <head>
    <style>
      .test {color: green;}
      p {color: red;}
    </style>
  </head>
  <body>
  <p class="test">Hello World!</p>
  </body>
  </html>
\end{lstlisting}


Każdy selektor CSS ma swoje miejsce w hierarchii specyficzności.

Istnieją cztery kategorie, które określają poziom specyficzności selektora:
\begin{itemize}
  \item style liniowe -- specyficzność 1000, na przykład: \lstinline{<h1 style="color: pink;">};
  \item identyfikatory -- specyficzność 100, na przykład: \lstinline{#navbar};
  \item klasy, pseudo-klasy, selektory atrybutów -- specyficzność 10, na przykład: \lstinline{.test}, \lstinline{:hover}, \lstinline{[href]};
  \item elementy i pseudo-elementy -- specyficzność 1, na przykład: \lstinline{h1}, \lstinline{::before}.
\end{itemize}
Dodatkowo, selektor uniwersalny posiada specyficzność 0.

Znaczenie też ma kolejność reguł. Reguły definiowane później w arkuszu CSS mają potencjalnie możliwość nadpisania wcześniejszych reguł, pod warunkiem, że mają równą lub wyższą specyfikę.

Tabela \ref{tabela_specyficznosci} pokazuje przykłady obliczenia specyficzności.

\section{Style warunkowe (ang. \emph{media query})}
Style warunkowe, są kluczowe dla responsywnego projektowania interfejsów. Pozwalają one dostosować wygląd stron internetowych do różnych urządzeń i warunków przeglądania. Składnia styli warunkowych w kodzie CSS jest opisana na listingach \ref{stylesheet_media} i \ref{media_list}.


\begin{lstlisting}[caption={Składnia styli warunkowych \cite{GrammarofCSS}}, label={stylesheet_media}]
media
  : MEDIA_SYM S* media_list '{' S* ruleset* '}' S*
  ;
media_list
  : medium [ COMMA S* medium]*
  ;
medium
  : IDENT S*
  ;
\end{lstlisting}

\begin{lstlisting}[caption={Składnia tokena \lstinline|MEDIA_SYM| zwracanego przez lekser CSS \cite{GrammarofCSS}}, label={media_list}]
  @{M}{E}{D}{I}{A}
\end{lstlisting}

Przykładami wykorzystania stylów warunkowych są:
\begin{itemize}
  \item zmiana stylów zależnie od szerokości ekranu -- listing \ref{media_width},
  \item ograniczenie animacji zgodnie z preferencją użytkownika -- listing \ref{media_prefer}.
\end{itemize}

\begin{lstlisting}[caption={Kod CSS zmieniający szerokość elementu zależnie od szerokości ekranu}, label={media_width}]
  .container {
    width: 100%;
  }

  @media (min-width: 768px) {
    .container {
      width: 75%;
    }
  }
\end{lstlisting}

\begin{lstlisting}[caption={Kod CSS ograniczający animacje zgodnie z preferencją użytkownika}, label={media_prefer}]
  @media (prefers-reduced-motion: no-preference) {
    .spin {
      animation: spin 1s linear infinite;
    }
  }
\end{lstlisting}

\chapter{Problemy języka CSS}
\section{Rosnące rozmiary plików}
Im większy plik CSS, tym dłużej zajmie mu załadowanie się na stronie internetowej. Duży rozmiar plików może powodować spowolnienie czasu ładowania strony, co z kolei może prowadzić do niższej oceny strony w wynikach wyszukiwania i gorszego doświadczenia użytkownika.

W sytuacji, kiedy wielu programistów równolegle ręcznie tworzy kod CSS, dochodzi do powtórzeń kodu. Tego typu praca wymaga regularnej optymalizacji i refaktoryzacji kodu w celu zmniejszenia jego rozmiaru. Proces ten wraz z czasem staje się coraz dłuższy i droższy ze względu na rosnący rozmiar kodu.

Na rosnący rozmiar kodu wpływ ma też niewykorzystywany kod CSS. Wraz ze zmianą struktury HTML, część stylów staje się nieużywana. Style te często nie są łatwe do znalezienia, ze względu na złożoność zastosowanych selektorów i trudność analizy kodu HTML, np. struktura HTML zmienia się pod wpływem kodu JavaScript.
\section{Kolizje pomiędzy stylami}
\subsection{Zmiana reguł bazowych}

Deweloperzy muszą używać elementów HTML do pisania HTML, a liczba elementów, które można wybrać, jest ograniczona. Dlatego może to być kuszące, aby zdefiniować wiele podstawowych stylów za pomocą selektorów elementów, aby uniknąć dodawania klas do wszystkich elementów, to takie podejście tworzy niezadeklarowaną zależność między tymi regułami a wszystkimi innymi komponentami.


Kiedy zaczynamy budować stronę internetową, zazwyczaj nie wydaje się to dużym problemem, wręcz przeciwnie, wydaje się to naturalne i zgodne z zasadą DRY (Don't Repeat Yourself). Tworzymy bazowe, podstawowe style (marginesy, rozmiary czcionek, kolory itp.), a następnie budujemy komponenty na ich podstawie, dzięki czemu nie musimy ponownie definiować tych samych reguł \cite{SideEffects}.

Problem polega na tym, że oszczędzamy czas tylko pod warunkiem, że nigdy nie zmienimy swoich bazowych reguł. W praktyce projekty stron internetowych się zmieniają. Możemy zdecydować się na zwiększenie rozmiaru czcionki nagłówków, zastosowanie innych domyślnych marginesów dla akapitów, lub że wolimy obramowania zamiast podkreśleń dla linków. Jeśli komponenty takie jak \lstinline|.article-title|, \lstinline|.alert-content| i \lstinline|.footer-link| zależą od tych bazowych reguł, szybko zauważymy, jak kruche i powiązane są nasze style.

Jeśli komponenty zależą od bazowych stylów, zmiany w tych bazowych stylach będą wymagały sprawdzenia całej strony, aby upewnić się, że wszystko wciąż wygląda poprawnie \cite{SideEffects}.

\subsection{Kolizje nazw klas}


CSS nie ostrzega, jeśli używa się selektora klasy, który już istnieje w arkuszu stylów. Możliwość nadpisywania reguł jest jedną z cech tego języka. W rezultacie, bez wprowadzenia konwencji unikającej takich przypadków lub bez sprawdzania tego podczas budowania projektu, nie ma dobrego sposobu, aby upewnić się, że wybrana klasa, nie została już użyta przez kogoś innego.

Gdy wielu deweloperów pracuje nad tym samym kodem, szansa, że dwie osoby wybiorą tę samą nazwę klasy i nie będą o tym wiedziały, jest bardzo wysoka. Dotyczy to szczególnie powszechnych nazw, takich jak \lstinline|button|, \lstinline|content| czy \lstinline|title|.

Nie jest to problem tylko z nazwami klas na najwyższym poziomie. Wybranie tej samej nazwy w poddrzewie może być równie niebezpieczne  \cite{SideEffects}.
\section{Rozmieszczanie klas pomiędzy plikami CSS}
Jeśli style są umieszczone bezpośrednio w plikach HTML, trudno jest je ponownie wykorzystać w innych częściach strony lub w innych projektach. Tego typu kolokacja stylów prowadzi do braku wyraźnej separacji między treścią, a jej prezentacją, co utrudnia zrozumienie struktury strony.

W dużych projektach stylizacje mogą być rozproszone po wielu plikach. Na przykład, style dla przycisków mogą znajdować się w jednym pliku, dla formularzy w innym, a dla nagłówków jeszcze w innym. Odszukanie i modyfikacja stylów staje się czasochłonne, zwłaszcza gdy trzeba dokonać globalnych zmian.

\chapter{Funkcjonalności bibliotek Tailwind CSS}
Tailwind CSS to framework pełen klas takich jak \lstinline|flex| \lstinline|pt-4| \lstinline|text-center|, które można komponować bezpośrednio w kodzie HTML.

\section{Sposoby integracji}
Z Tailwind CSS możemy skorzystać niezależnie od wykorzystywanego języka programowania, wystarczy wywołać komendę generującą akrusz stylów w terminalu. Dzięki temu, proces ten można bez problemu zautomatyzować praktycznie w każdym projekcie np. w projekcie C++ korzystającym z narzędzia takiego jak \lstinline|CMake|, lub projekcie Java korzystającym z narzędzia \lstinline|Gradle|, \lstinline|Maven|. W naszym przypadku wykorzystaliśmy plugin PostCSS.




\section{Warianty}
Każda klasa może być prefiksowane dowolną ilością wariantów. Warianty sprawiają, że reguła jest nakładana tylko w odpowiednich warunkach, np. \lstinline|hover:bg-red-500|, \lstinline|sm:hover:bg-red-500|.

\section{Konfigurowalność}
Tailwind CSS posiada zestaw wbudowanych klas i wartości, które są w pełni konfigurowalne. Możemy tworzyć nowe klasy, warianty, zmieniać domyślne wartości istniejących klas.

\section{Dowolne wartości}
W przypadku gdy nie skonfigurowaliśmy jakiejś klasy, wariantu lub nie planujemy ich więcej używać, Tailwind CSS pozwala na użycie dowolnych wartości bez takiej potrzeby, np. \lstinline|bg-[#764]|, \lstinline|m-[1px]|, \lstinline|[appearance:textfield]|, \lstinline|group-has-[.suffix]:text-right|, \lstinline|[&::-webkit-inner-spin-button]:hidden|
\section{Selektory}
\subsection{Selektor elementów, uniwersalny, id, klasy, grupujący}
Tailwind CSS nie posiada wbudowanych selektorów elementów, selektora uniwersalnego, selektora id, selektora klasy i selektorów grupujących. W tych przypadkach możemy zdefiniować reguły w pliku CSS. Możemy też stworzyć klasę wykorzystującą dowolny selektor np. selektor elementów tak jak na listingu \ref{tailwind_element_selector} i \ref{tailwind_child_element_selector}. Tworząc klasę w ten sposób musimy wykorzystać znak \lstinline|&| odnoszący się do elementu, na którym znajduje się klasa, więc nie ma możliwości stworzenia klasy odnoszącej się do wszystkich elementów na stronie chyba, że umieścimy klasę na elemencie \lstinline|html| będącym korzeniem drzewa HTML.


\begin{lstlisting}[language=HTML, caption={Klasa zmieniająca padding dla elementu będącego elementem \lstinline|a|}, label={tailwind_element_selector}]
<!--
  a.\[a\&\]\:p-2 {
    padding: 0.5rem/* 8px */;
  }
-->
<div class="[a&]:p-2"></div>
\end{lstlisting}

\begin{lstlisting}[language=HTML, caption={Klasa zmieniająca padding dla przodków będących elementem \lstinline|a|}, label={tailwind_child_element_selector}]
<!--
  .\[\&_a\]\:p-2 a {
    padding: 0.5rem/* 8px */;
  }
-->
<div class="[&_a]:p-2"></div>
\end{lstlisting}
\subsection{Selektor potomków}
Tailwind CSS posiada zestaw wbudowanych wariantów \lstinline|group|, które pozwalają na stylizację potomka zależnie od stanu przodka. Dla przykładu na listingu \ref{tailwind_se_selektor} widzimy, klasę \lstinline|group-hover:bg-red-500| która zmieni kolor tła akapitu na czerwony, gdy użytkownik najedzie na sekcję myszką. Klasa \lstinline|group| sama w sobie nie nakłada żadnych styli, jest nakładana tylko w celu odniesienia się potomka do elementu. Istnieje też możliwość nadania grupom nazw, co może być używane w celu zagnieżdżania grup, np. \lstinline|group/item|, \lstinline|group-hover/item:bg-red-500|.

\begin{lstlisting}[language=HTML, caption={Przykład wykorzystanie klasy \lstinline|group|}, label={tailwind_se_selektor}]
  <section class="group">
    <div>
      <p class="group-hover:bg-red-500">Hello world!</p>
    </div>
  </section>
\end{lstlisting}

\subsection{Selektor dziecka}
Tailwind CSS posiada wbudowany wariant \lstinline|*|, który pozwala na stylizację dziecka. Dla przykładu na listingu \ref{tailwind_c_selektor} widzimy, klasę \lstinline|*:bg-red-500| która zmieni kolor tła elementu div na czerwony.

\begin{lstlisting}[language=HTML, caption={Przykład wykorzystania selektora dziecka}, label={tailwind_c_selektor}]
  <section class="*:bg-red-500">
    <div>
      <p>Hello world!</p>
    </div>
  </section>
\end{lstlisting}

\section{Selektor młodszego rodzeństwa}
Tailwind CSS posiada zestaw wbudowanych wariantów \lstinline|peer|, które pozwalają na stylizację młodszego rodzeństwa zależnie od stanu starszego rodzeństwa. Dla przykładu na listingu \ref{tailwind_s_selektor} widzimy, klasę \lstinline|peer-hover:bg-red-500| która zmieni kolor tła akapitu na czerwony, gdy użytkownik najedzie na sekcję myszką. Klasa \lstinline|peer| sama w sobie nie nakłada żadnych styli, jest nakładana tylko w celu odniesienia się młodszego rodzeństwa do elementu. Istnieje też możliwość nadania nazw, co może być używane w celu odniesienia do wielu elementów, np. \lstinline|peer/item|, \lstinline|peer-hover/item:bg-red-500|.

\begin{lstlisting}[language=HTML, caption={Przykład wykorzystanie klasy \lstinline|peer|}, label={tailwind_s_selektor}]
  <section class="peer"></section>
  <div></div>
  <p class="peer-hover:bg-red-500">Hello world!</p>
\end{lstlisting}

\section{Selektor sąsiadującego młodszego rodzeństwa}
Tailwind CSS nie posiada wbudowanego selektora sąsiadującego młodszego rodzeństwa. Jeżeli istnieje potrzeba jego użycia to można posłużyć się konfiguracją w celu stworzenia wariantów analogicznie jak w przypadku selektora młodszego rodzeństwa (klasa \lstinline|peer|). Lub można użyć dowolnych wartości jak w przypadku innych niewbudowanych selektorów.

\section{Pseudo-klasy i pseudo-elementy}
Tailwind CSS posiada wbudowane warianty dla większości pseudo-klas i pseudo-elementów, np. \lstinline|hover:bg-red|, \lstinline|first:bg-red|, \lstinline|first:focus:bg-red|. Możemy też posłużyć się konfiguracją w celu stworzenia nowych wariantów, np. \lstinline|addVariant('hocus', ['&:hover', '&:focus'])|.
\subsection{Funkcyjne pseudo-klasy}
Tailwind CSS posiada kilka wbudowanych pseudo-klas, ich użycie wymaga podania dowolnej wartości, np. na listingu \ref{tailwind_fn} styl elementu div zmieni się tylko wtedy, gdy element posiada zaznaczone pole wyboru.

\begin{lstlisting}[label={tailwind_fn}, language=HTML]
<!--
.has-\[input\:checked\]\:p-2:has(input:checked) {
  padding: 0.5rem/* 8px */;
}
-->
<div class="has-[input:checked]:p-2">...</div>
\end{lstlisting}

\section{Style warunkowe (ang. \emph{media query})}
Tailwind CSS posiada wbudowane warianty dla większości stylów warunkowych, np. \lstinline|motion-reduce:hidden|, \lstinline|dark:bg-red|. Wbudowane zostały również warianty dla popularnie wykorzystywanych szerokości ekranów, \lstinline|sm| - 640px, \lstinline|md| - 768px, \lstinline|lg| - 1024px, \lstinline|xl| - 1280px, \lstinline|2xl| - 1536px.  Możemy też posłużyć się konfiguracją w celu stworzenia nowych wariantów, np. \lstinline|addVariant('starting-style', ['@starting-style{&}'])|.
\section{Zmienne CSS}
Aby użyć zmiennych Tailwind CSS wymaga podania zmiennej jako dowolnej wartości, np. \lstinline|bg-[var(--bg-color)]|.

\section{Nadpisywanie stylów}
Tailwind CSS nie posiada możliowości nadpisywania stylów. Nakładając dwie klasy, np. \lstinline|p-2| i \lstinline|p-4| nie mamy kontroli nad tym która będzie miała większy priorytet. W takim wypadku możemy sprefixować jedną z klas znakiem \lstinline|!|, np. \lstinline|!p-2| aby stworzyć regułę z deklaracją \lstinline|!important| w celu nadpisania stylów. Nie jest to jednak zalecane, gdyż taką operację można zastosować tylko raz i wymaga wygenerowania dodatkowego kodu CSS.
\chapter{Funkcjonalności biblioteki StyleX}

\section{Przestrzenie nazw}
Style muszą być tworzone przy użyciu funkcji \lstinline|stylex.create|. Dzięki której możemy zdefiniować jedną lub więcej przestrzeń nazw, np. na listingu \ref{stylex_create} widzimy, że zdefiniowano dwie przestrzenie nazw: \lstinline|base| oraz \lstinline|highlighted|. Nazwy mogą być wybrane dowolnie.

\begin{lstlisting}[caption={Przykład tworzenia przestrzeni nazw}, label={stylex_create}]
import * as stylex from '@stylexjs/stylex';

const styles = stylex.create({
  base: {
    fontSize: 16,
    lineHeight: 1.5,
    color: 'rgb(60,60,60)',
  },
  highlighted: {
    color: 'rebeccapurple',
  },
});
\end{lstlisting}

\section{Selektory}
Biblioteka StyleX pozwala na stylizację elementów jedynie poprzez klasy, nie ma możliwości użycia reszty selektorów. Jest to intencjonalnie nałożone ograniczenie w celu stworzenia szybkiego i przewidywalnego systemu stylizacji.
\section{Pseudo-klasy}
Biblioteka StyleX pozwala na używanie pseudo-klas, np. na listingu \ref{style_x_pseudo_klasy} widzimy, że aby zmienić kolor przycisku zależnie od stanu pseudo-klas \lstinline|:hover| oraz \lstinline|:focus|, wartość klucza \lstinline|backgroundColor| została zastąpiona obiektem pseudo-klas.

\begin{lstlisting}[caption={Przykład wykorzystania pseudo-klasy}, label={style_x_pseudo_klasy}]
  import * as stylex from '@stylexjs/stylex';

  const styles = stylex.create({
    button: {
      backgroundColor: {
        default: 'lightblue',
        ':hover': 'blue',
        ':active': 'darkblue',
      },
    },
  });
\end{lstlisting}
\section{Pseudo-elementy}
Biblioteka StyleX pozwala na stylizację pseudo-elementów. Na listingu \ref{style_x_pseudo_element} widzimy, że aby zmienić kolor pseudo-elementu \lstinline|::placeholder| musimy umieścić jego w przstrzeni nazw.

\begin{lstlisting}[caption={Przykład stylizacji pseudo-elementu}, label={style_x_pseudo_element}]
  import * as stylex from '@stylexjs/stylex';

  const styles = stylex.create({
    input: {
      // pseudo-element
      '::placeholder': {
        color: '#999',
      },
      color: {
        default: '#333',
        // pseudo-class
        ':invalid': 'red',
      },
    },
  });
\end{lstlisting}

\section{Style warunkowe (ang. \emph{media query})}
Biblioteka StyleX pozwala na używanie styli warunkowej, w sposób analogiczny jak używanie pseudo-klas, np. na listingu \ref{style_x_warun} widzimy, że aby zmienić kolor przycisku zależnie od rozdzielczości ekranu, wartość klucza \lstinline|backgroundColor| została zastąpiona obiektem styli.

\begin{lstlisting}[caption={Przykład wykorzystania styli warunkowych}, label={style_x_warun}]
  import * as stylex from '@stylexjs/stylex';

  const styles = stylex.create({
    button: {
      backgroundColor: {
        default: 'lightblue',
        '@media (max-width: 800px)': 'blue',
        '@media (max-width: 1540px)': 'darkblue',
      },
    },
  });
\end{lstlisting}
\section{Zmienne CSS}
Biblioteka StyleX pozwala na używanie zmiennych CSS, poprzez zastąpienie przestrzenie nazw funkcją przyjmującą wartości zmiennych jako argumenty i zwracającą przestrzeń nazw, wyglądającą tak jak dotychczas. Dla przykładu na listingu \ref{stylex_css} widzimy, że wartość \lstinline|height| została zastąpiona wartością dynamiczną. Używana w ten sposób funkcja nie może posiadać żadnych instrukji poza zwracaną przestrzenią nazw, nie będzie mogła być zanalizowana na etapie kompilacji.

\begin{lstlisting}[caption={Przykład użycia zmiennych CSS}, label={stylex_css}]
import * as stylex from '@stylexjs/stylex';

const styles = stylex.create({
  bar: (height) => ({
    height,
  }),
});

function MyComponent() {
  // The value of `height` cannot be known at compile time.
  const [height, setHeight] = useState(10);

  return <div {...stylex.props(styles.bar(height))} />;
}
\end{lstlisting}
\section{Nadpisywanie stylów}
Biblioteka StyleX posiada funkcję \lstinline|stylex.props| która jako argumenty przyjmuje listę przestrzeni nazw i łączy je w deterministyczny sposób `ostatni styl zawsze wygrywa'.

Dla przykładu na listingu \ref{stylex_props} widzimy, że element \lstinline|div| będzie miał fioletowy kolor, jeżeli kolejność argumentów była by odwrócona, element miałby kolor szary.

\begin{lstlisting}[caption={Przykład nadpisywania stylów}, label={stylex_props}]
import * as stylex from '@stylexjs/stylex';

const styles = stylex.create({
  base: {
    fontSize: 16,
    lineHeight: 1.5,
    color: 'grey',
  },
  highlighted: {
    color: 'rebeccapurple',
  },
});

<div {...stylex.props(styles.base, styles.highlighted)} />;
\end{lstlisting}

\section{Zmienne}
Zarówno czysty CSS jak i biblioteka Tailwind CSS i biblioteka StyleX pozwalają na użycie zmiennych.

W przypadku naszej aplikacji użyliśmy zmiennych w celu zdefiniowania wszystkich używanych kolorów. Umożliwiło nam to całkowitą zmianę wyglądu strony zależnie od zdefiniowanego przez nas motywu. Zdefiniowaliśmy motywy \lstinline|light| i \lstinline|dark|.




Na listingu \ref{variables} widzimy, że w przypadku użycia biblioteki StyleX zmienne i motym zadeklarowaliśmy w oddzielnym pliku JavaScript. Na listingu \ref{stylex_theme} widzimy, że aby zastosować motyw musimy go ustawić jako wartość atrybutu \lstinline|style|. Na listingu \ref{stylex_vars} widzimy, że aby użyć wartości zmiennych używamy funkcji \lstinline|stylex.create| aby stworzyć nową przestrzeń nazw w której przekazujemy wartość zmiennej \lstinline|surface| jako wartość atrybutu \lstinline|backgroundColor|, oraz wartość zmiennej \lstinline|onSurface| jako wartość atrybutu \lstinline|color|. Następnie używamy funkcji \lstinline|stylex.props| aby nałożyć style z przestrzeni nazw na element \lstinline|div|.

\begin{lstlisting}[caption={StyleX definicja zmiennych CSS}, label={variables}]
import * as stylex from "@stylexjs/stylex";

export const colors = stylex.defineVars({
  "primary": "rgb(103 80 164)",
  "primaryContainer": "rgb(234 221 255)",
  //...
});

export const dark = stylex.createTheme(colors, {
  "primary": "rgb(208 188 255)",
  "primaryContainer": "rgb(79 55 139)",
  //...
});
\end{lstlisting}

\begin{lstlisting}[caption={StyleX nałożenie motywu}, label={stylex_theme}]
  import { dark } from "./tokens.stylex";
  <Wrapper style={dark}>
  {/* ... */}
  </Wrapper>
\end{lstlisting}

\begin{lstlisting}[caption={StyleX użycie zmiennych }, label={stylex_vars}]
import { colors } from "./tokens.stylex";

const styles = stylex.create({
  root: {
    backgroundColor: colors.surface,
    color: colors.onSurface,
    // ...
  },
  // ...
});

export default function Root(props: PropsWithChildren<{}>) {
  return (
    <div {...stylex.props(styles.root)}>
      {/* ... */}
    </div>
  );
}
\end{lstlisting}

Na listingu \ref{tail_variables} widzimy, że w przypadku użycia biblioteki Tailwind CSS rozszerzyliśmy zestaw wbudowanych kolorów \lstinline|colors| o nowe kolory, takie jak \lstinline|primary| oraz \lstinline|primary-container|, które odnoszą się do nazwy zmiennych. Roszerzenie to pozwoliło na używanie wbudowanych klas takich jak \lstinline|bg-primary-container|, \lstinline|text-primary|. Stworzyliśmy również plugin pozwalający na użycie różnych motywów.

Na listingu \ref{tailwind_theme} widzimy, że aby zastosować motyw musimy jedynie nałożyć klasę \lstinline|dark|. Na listingu \ref{tailwind_vars} widzimy, że aby użyć wartości zmiennych używamy nowo wygenerowanych klas \lstinline|bg-surface| oraz \lstinline|text-on-surface|.

\begin{lstlisting}[caption={Tailwind CSS zmienne CSS}, label={tail_variables}]
const themes = {
  light: {
    "--primary": "103 80 164",
    "--primary-container": "234 221 255",
    //...
  },
  dark: {
    "--primary": "208 188 255",
    "--primary-container": "79 55 139",
    //...
  },
};

/** @type {import('tailwindcss').Config} */
module.exports = {
  theme: {
    extend: {
      colors: {
        ...Object.fromEntries(
          Object.keys(themes.light).map((color) => [
            color.substring(2),
            `rgb(var(${color}) / <alpha-value>)`,
          ])
        ),
      },
    },
  },
  plugins: [
    //...
    plugin(({ addBase }) => {
      addBase({
        ":root": themes.light,
        ".light": themes.light,
        ".dark": themes.dark,
      });
    }),
  ],
}
\end{lstlisting}

\begin{lstlisting}[caption={Tailwind CSS nałożenie motywu}, label={tailwind_theme}]
  <Wrapper className="dark">
    {/* ... */}
  </Wrapper>
\end{lstlisting}

\begin{lstlisting}[caption={Tailwind CSS użycie zmiennych }, label={tailwind_vars}]
export default function Root(props: PropsWithChildren<{}>) {
  return (
    <div className="bg-surface text-on-surface">
      {/* ... */}
    </div>
  );
}
\end{lstlisting}


\section{Kolokacja kodu}
Zagnieżdżanie selektorów pozwala na zwiększenie czytelności kodu CSS, poprzez grupowanie powiązanych reguł. Na przykład na listingu \ref{nesting} widzimy, że reguła \lstinline|&.btn--primary| i \lstinline|&:hover| są zagnieżdżone w regułę \lstinline|.btn|. Takie zagnieżdżenie jest równoważne z regułami o selektorach \lstinline|.btn.btn--primary| oraz \lstinline|.btn:hover|. Zagnieżdżając można korzystać ze wszystkich selektorów, nie można jednak zagnieżdżać styli warunkowych.

\begin{lstlisting}[caption={Zagnieżdżanie reguł w CSS}, label={nesting}]
.btn {
  &.btn--primary {
    color: red;
  }
  &:hover {
    color: blue;
  }
}

@media (min-width: 768px) {
  .btn:hover {
      color: purple;
  }
}
\end{lstlisting}


StyleX pozwala na grupowanie reguł za pomocą przestrzeni nazw, w której korzystać można z styli warunkowych, oraz zagnieżdżać pseudo-klasy i pseudo-elementy. StyleX natomiast nie pozwala na używanie reszty selektorów. Reguły CSS na listingu \ref{nesting} wymagają napisanie podobnej ilości kodu co równoważne reguły StyleX na listingu \ref{stylex_nesting}.

\begin{lstlisting}[caption={Zagnieżdżanie reguł w StyleX}, label={stylex_nesting}]
const styles = stylex.create({
  btn: {
    ':hover': 'blue',
    '@media (min-width: 768px)': {
      ':hover': {
        color: 'purple',
      }
    }
  },
  btnPrimary: {
    color: 'red',
  }
})
\end{lstlisting}

W przypadku TailwindCSS to struktura kodu HTML odpowiada za grupowanie użytych klas. Kod na listingu \ref{tailwind_nesting} wymaga najmniejszej ilości kodu. Musimy natomiast pamiętać, że kod ten musi być napisany, ze każdym razem, gdy umieszczamy przycisk na stronie. Aby nie powtarzać kodu musimy skorzystać z dowolnej biblioteki pozwalającej na tworzenie komponentów wielokrotnego użytku.




\begin{lstlisting}[language=HTML, caption={Grupowanie reguł w Tailwind CSS}, label={tailwind_nesting}]
  <button class="hover:text-blue sm:hover:text-purple [&.primary]:text-red">
  ...
  </button>
\end{lstlisting}

\section{Prefiksy}
W przypadkach gdy przeglądarki nie wspierają nowych wartości w CSS można zdefiniować dany atrybut wielokrotnie. Na przykład na listingu \ref{prefix} widzimy, że atrybut \lstinline|position| został zdefiniowany wielokrotnie. Jeśli przeglądarka nie wspiera wartości atrybutu \lstinline|sticky| to ją pominie i spróbuje zastosować wartość \lstinline|-webkit-sticky| itd.

\begin{lstlisting}[caption={Prefiksy w CSS}, label={prefix}]
.header {
  position: fixed;
  position: -webkit-sticky;
  position: sticky;
}
\end{lstlisting}

W przypadku biblioteki StyleX można użyć funkcji \lstinline|stylex.firstThatWorks| aby zdefiniować wiele wartości. Na listingu \ref{stylex_prefix} widać style StyleX równoważne z regułami CSS na listingu \ref{prefix}.
\begin{lstlisting}[caption={Prefiksy w StyleX}, label={stylex_prefix}]
const styles = stylex.create({
  header: {
    position: stylex.firstThatWorks('sticky', '-webkit-sticky', 'fixed'),
  },
});
\end{lstlisting}

Biblioteka Tailwind CSS nie pozwala na zdefiniowanie jednego atrybutu wielokrotnie w deterministycznej kolejności. Sugerowany sposób na dodanie wsparcia dla różnych przeglądarek to zastosowanie osobnej biblioteki w celu przekształcenia wynikowych stylów, np. używająć biblioteki \lstinline|PostCSS| możemy zainstalować plugin \lstinline|autoprefixer|, który automatycznie dodaje prefiksy dla różnych przeglądarek. Alternatywnie możemy użyć stylów warunkowych, np. \lstinline|fixed supports-[position:-webkit-sticky]:[position:-webkit-sticky] supports-[position:sticky]:sticky|.

\section{Deduplikacja kodu}
Deduplikacja kodu jest procesem usuwania duplikatów kodu. W przypadku biblioteki StyleX jak i Tailwind CSS obie biblioteki analizują kod źródłowy i generują optymalny kod CSS. Na przykład na listingu \ref{deduplication} widać kod przed kompilacją, a na listingu \ref{deduplication_after} po skompilowaniu. Wartości atrybutów zastępowane są nazwami klas. Wszystkie kolejne użycie atrybutów o identycznych wartościach w innych częściach kodu zostaną zastąpione tą samą nazwą klasy, dzięki czemu rozmiar kodu CSS nie zmieni się.

\begin{lstlisting}[caption={Kod przed kompilacją}, label={deduplication}]
const styles = stylex.create({
  foo: {
    color: 'red',
    backgroundColor: 'blue',
  },
  bar: {
    color: 'red',
  },
});
\end{lstlisting}

\begin{lstlisting}[caption={Kod po skompilowaniu}, label={deduplication_after}]
const styles = {
  foo: {
    color: 'x1e2nbdu',
    backgroundColor: 'x1t391ir',
    $$css: true,
  },
  bar: {
    color: 'x1e2nbdu',
    $$css: true,
  },
};
\end{lstlisting}

\section{Nadpisywanie stylów}
Język CSS posiada ograniczone możliwości nadpisywania stylów. W tym celu możemy użyć selektora o większej specyficzności, lub deklaracji \lstinline|!important|. Oba te sposoby mogą prowadzić do nieprzewidzianych błędów w przyszłości.

Tailwind CSS nie posiada dodatkowych możliwości nadpisywania stylów, poza tymi oferowanymi przez czysty CSS.

StyleX pozwala na deterministyczne nadpisywanie stylów, ostatni nałożony styl wygrywa.
